# 질문 매핑표

리뷰에서 정의 없음 또는 불충분으로 판정된 소항목과 초안의 빈칸 `[Q번호]`를 이 표의 질문으로 바꾼다. 답이 오면 지정된 섹션과 열에 채운다. 적용 유형이 맞지 않는 소항목은 묻지 않는다

## 질문 묶음 규칙

- 우선순위 A(착수 차단), B(중요), C(보완). 빈칸과 리뷰 결과를 우선순위 순으로 정렬하고, 같은 등급 안에서는 대항목 순서
- 한 번에 5개 안팎, 기본 2회. 2회가 끝났는데 A 항목이 남아 있으면 "착수 전 확인 필요 항목 N건이 남았습니다. 한 번 더 물을까요?"라고 한 번만 제안하고, 작성자가 원하면 3회차, 아니면 바로 본문으로
- 계수 단위는 문서의 ⚠️ 하나. 빈칸 `[Q번호]`도 본문에서는 ⚠️로 바뀌므로 같은 단위. A 등급(이 표의 A 행에 대응하는 것, 또는 그것 없이는 개발이 시작을 못 하는 것)은 반드시 `⚠️ 착수 조건: {내용} → {주체} 확인 필요` 꼴로 쓴다. 착수 전 건수는 `⚠️ 착수 조건` 문자열 수. 근거 첨부(`쿼리 첨부 필요`), 렌더 실패, `개발 제안 요청`, 목표값 미정(Secondary)은 A가 아니므로 `착수 조건` 없이 `⚠️ {내용} → {주체} 확인 필요`
- 질문 전에 한 줄 요약: "확인 필요 {⚠️ 수}건 중 착수 전 {A 수}건을 먼저 묻습니다". 여기서 ⚠️ 수는 초안의 빈칸 `[Q]`와 ⚠️를 합한 수이고, 저장 안내의 수와 같은 단위
- 개방형이 기본. 선택지는 답이 정해진 집합(플랫폼, 유저 유형, 저장 시점)일 때만 쓰고, 선택지에는 항상 "모름"을 넣는다. AskUserQuestion 도구가 있으면 선택지형 질문에만 쓴다
- 유도 질문 금지. "로그인 유저만 보이죠?"처럼 AI 추정값을 먼저 제시하고 동의를 구하지 않는다. 초안의 추정을 확인받고 싶으면 "초안에는 {값}으로 두었습니다. 맞나요, 아니면 다른가요?"처럼 초안 값임을 밝힌다
- 질문 문안의 `{기능}`, `{화면}` 자리는 초안의 실제 이름으로 채움
- 답이 오면 `sources.md`에 "구술"로 기록. 답이 초안과 어긋나면 답을 채택하고 초안을 고침
- 답이 없거나 "모름", "나중에"인 항목은 본문의 해당 셀에 `⚠️ {항목} → {결정 주체} 확인 필요`로 남기고 지어내지 않음. 결정 주체는 항목 성격으로 정함 (권한과 정책은 DRI, 화면과 카피는 디자인, 동작과 API는 개발)
- 질문이 끝나면(2회 또는 3회) 답이 없는 항목을 전부 ⚠️로 남기고 본문을 만든다. 남은 A 등급 항목 수는 문서 첫 줄과 저장 안내에 "착수 전 확인 필요 {N}건"으로 크게 적는다. 작성자가 중간에 그만하자고 해도 같은 방식으로 처리하고, 어떤 경우에도 빈칸을 추론으로 채우지 않는다
