# 와이어프레임 (WDS, 한 장짜리)

스펙의 화면을 노션 페이지처럼 한 페이지에 세로로 늘어놓은 HTML. 화면마다 요구사항 목록과 WDS로 그린 와이어프레임을 같이 둔다. 버튼, 탭, 입력, 모달이 동작한다

- 대상: 디자인 착수 전 화면 구성과 이동을 디자이너, 개발자와 맞추는 용도
- 화면 프로토타입(SKILL.md 「아티팩트 생성」)과 다른 점
  - 프로토타입: 화면을 하나씩 전환해 실제 앱처럼 누름
  - 와이어프레임: 모든 화면을 한 페이지에서 훑고, 화면끼리 이동은 스크롤로 보여줌

## 만드는 조건

- Phase 4 아티팩트 질문에서 작성자가 3번(와이어프레임)을 고른 경우
- 작성자가 스펙 작성 뒤 "와이어프레임 만들어줘"라고 한 경우
- 스펙이 없으면 만들지 않는다. "스펙을 먼저 만들어야 합니다" 한 줄 안내

## 먼저 읽을 것

1. `references/wireframe-template.html`: 양식, 컴포넌트 클래스, 동작 속성. 이 파일을 복사해서 시작
2. 대상 스펙 `docs/specs/{슬러그}/spec.md`의 화면 표 또는 구현 상세, 상태 표, 버튼/액션 표
3. 원티드 몽타주 MCP(`list_tokens`, `get_component`)가 연결돼 있으면 양식의 색 값이 토큰과 같은지, 쓸 컴포넌트의 variant 이름이 맞는지 확인. 다르면 MCP 값을 따름

## 화면 고르기

- 화면 하나가 `<section class="screen" id="{화면 ID}">` 하나
- 순서: 스펙의 유저향 화면 → 어드민 화면 → 원티드 화면 변경(W1, W2). 목차도 같은 순서로 그룹을 나눔
- Feature, Enhancement 스펙은 구현 상세의 화면 열('화면 > 영역')을 화면 이름으로 묶어 섹션 하나로
  - 기존 화면이면 바뀌는 영역만 그리고, 나머지는 `.w-skel` 자리로 둠
  - 화면 열이 `해당 없음 ({종류})`인 행은 그리지 않고 맨 아래 「화면 밖 동작」 섹션에 요구사항 목록만
- 프레임: 모바일이면 `.frame`, PC면 `.frame.pc`. 스펙 메타의 플랫폼이 둘 다면 모바일 먼저

## 화면 안에 넣는 것

- 요구사항 `ul.req`: 스펙 행의 요구사항을 문구 그대로. 고쳐 쓰거나 요약하지 않음
  - 프레임 안에 대응 요소가 있으면 `li`에 `data-target="요소 id"`
  - `⚠️ 착수 조건`과 `(PO 확인 필요)` 같은 괄호 표시도 그대로 옮김
- 진입점 `.entry`: 스펙의 진입점 열 그대로
- 프레임 안 요소: 스펙에 적힌 구성요소만. 적히지 않은 탭, 필터, 버튼, 배너를 더하지 않는다 (SKILL.md 「하지 않는 것」과 같음)
- 문구: 스펙에 확정 문구가 있으면 그대로, 없으면 요소 이름 + `(문구 워싱 필요)`
- 이미지, 아이콘, 사진: 넣지 않음. `.w-thumb`에 '썸네일', '대표 이미지'처럼 자리 이름만
- 본문 텍스트 덩어리: `.w-skel` 줄로 대신함

## 동작

양식의 `data-` 속성만 쓴다. 새 스크립트를 짜지 않음

- 다른 화면으로 가는 버튼, 카드, 목록: `data-go="{화면 ID}"`. 스펙의 진입점 열과 맞춰서 연결
- 확인 창: `data-open`, `data-close`
- 필수 입력: 스펙에 필수라고 적힌 항목만 `.w-field[data-required]`와 `data-validate`
- 완료 알림: `data-toast`
- 상태에 따라 화면이 바뀌면(정원 참, 로그인 여부, 신청 여부) 시연 칩 `data-state` + `data-show-when`. 칩 옆에 '시연:' 표시를 남겨 실제 화면 요소가 아님을 알림
- 서버 처리, 저장, 로그인은 흉내 내지 않음

## 디자인 규칙

- 색, 글자 크기, 둥글기는 양식의 CSS 변수만. hex 값을 새로 쓰지 않음
- 강조색은 브랜드 파랑 하나. 상태 배지만 `.w-badge.negative`, `.brand`
- 와이어프레임이라 장식(그라데이션, 그림자 추가, 일러스트)을 넣지 않음
- 외부 CDN, 웹폰트 파일, 이미지 파일 없이 단일 HTML

## 저장과 전달

- 저장: `docs/specs/{슬러그}/wireframe.html`
- 스펙 1-7 참고(또는 비주얼 표)에 경로를 한 줄로 넣음
- 아티팩트를 올릴 수 있는 환경이면 같은 파일을 아티팩트로 올리고, 채팅에는 한 줄만: "와이어프레임: docs/specs/{슬러그}/wireframe.html"
- 파일에 사내 API 경로나 이벤트명을 넣지 않음. 요구사항 문구에 식별자가 있으면 그 줄은 뺌
- 파일 시스템이 없으면 HTML 전체를 출력

## 확인 (저장 뒤)

- 스펙 화면 행마다 섹션이 하나씩 있고, 목차 링크가 모두 이어지는가
- 모든 `data-go`, `data-target`, `data-open` 값이 실제 id를 가리키는가 (브라우저에서 열거나 grep으로 대조)
- 스펙에 없는 요소가 프레임에 없는가
- 요구사항 문구가 스펙과 같은가
- 모바일 폭(375px)에서 프레임이 넘치지 않는가

## 스펙이 바뀌면

- 스펙을 먼저 고치고, 바뀐 화면 섹션만 다시 씀
- 화면이 새로 생기거나 지워졌는데 바로 반영하지 못하면 문서 제목 아래 `⚠️ 스펙 {날짜} 기준, 최신 아님` 한 줄
