### 1-2. 문제

- 세미나 신청을 설문 폼으로 받아서 정원 마감, 대기자 안내를 운영자가 손으로 함
- 신청자가 신청 상태를 확인할 곳이 없어 문의가 반복됨 (가상 수치: 세미나 1회당 문의 30건)
- 출석 기록이 남지 않아 다음 세미나 안내 대상을 고르기 어려움

### 1-3. 사용자 니즈

- 원티드 개인 유저
    - 관심 있는 세미나를 찾아 바로 신청하고, 신청 상태를 한곳에서 보고 싶음
- 세미나 운영자
    - 정원과 대기를 자동으로 관리하고, 출석 결과를 다음 안내에 쓰고 싶음

### 1-4. 가설

- **IF** 세미나 목록에서 바로 신청하고, 정원이 차면 대기로 자동 전환되고, 신청 상태를 내 신청 내역에서 볼 수 있으면
- **THEN** 신청 문의가 줄고, 세미나당 신청 수가 늘어난다
- **BECAUSE** 신청 과정에서 확인이 안 되는 단계가 사라져 중간 이탈이 줄어듦

### 1-5. 솔루션

- 신청: 세미나 상세에서 바로 신청. 정원이 차면 대기로 받음
- 운영: 운영자가 어드민에서 세미나를 만들고 모집 기간과 정원을 설정
- 출석: **호스트가 세미나 당일 출석을 체크하고, 결과는 다음 안내 대상 고르기에 씀**

## 2. 용어

| 용어 | 뜻 |
| --- | --- |
| 모집 기간 | - 운영자가 정한 신청 받는 기간<br>- 이 기간에만 신청과 대기 등록 가능 |
| 대기 | - 정원이 찬 뒤 받은 신청<br>- 앞 신청이 취소되면 순서대로 신청 완료로 바뀜 |
| 호스트 | - 세미나를 맡아 진행하는 사람<br>- 당일 출석을 체크함 |

### 2-1. 신청 상태

| 상태 | 뜻 | 누가 봄 | 쓸 수 있는 버튼 |
| --- | --- | --- | --- |
| 신청 완료 | 정원 안에 들어온 신청 | 신청자, 운영자 | 신청 취소 |
| 대기 | - 정원이 찬 뒤 받은 신청<br>- 앞 신청이 취소되면 신청 완료로 바뀜 | 신청자, 운영자 | 대기 취소 |
| 취소 | 신청자가 취소했거나 운영자가 반려한 신청 | 신청자, 운영자 | 다시 신청 (모집 기간 안) |
| 출석 | 호스트가 당일 출석을 체크한 신청 | 신청자, 운영자 | 없음 |

| 신청 취소 | 신청 완료, 세미나 시작 24시간 전까지 | - 취소로 바뀜<br>- 대기 1번이 신청 완료로 바뀌고 알림 |
| 출석 체크 | 세미나 당일, 호스트 | 신청 완료 → 출석 |

## 3. 서비스 구조

세미나 신청에는 화면이 세 군데 있음

- **세미나 목록**
    - 모집 중, 진행 예정, 종료된 세미나를 모아 보는 곳. 상세로 들어가 신청함
- **내 신청 내역**
    - 내가 신청한 세미나와 상태(신청 완료, 대기, 취소, 출석)를 보는 곳. 신청 취소도 여기서 함
- **어드민**
    - 운영자가 세미나를 만들고, 신청자를 승인하거나 반려하고, 출석 결과를 보는 곳

## 7. 공통 정책

- 7-3은 2차, 나머지는 1차

### 7-1. 정원과 대기

| 항목 | 내용 |
| --- | --- |
| 정원 | - 운영자가 세미나마다 정함<br>- 모집 중에는 늘리기만 가능 |
| 대기 | - 정원의 50%까지 받음 (가상 값)<br>- 대기도 차면 신청하기 버튼 비활성 + '신청이 마감됐어요' |
| 대기 전환 | - 신청 완료가 취소되면 대기 1번부터 신청 완료로 바뀜<br>- 바뀐 사람에게 알림 |

### 7-2. 신청 취소

| 항목 | 내용 |
| --- | --- |
| 누가 | - 신청자 본인<br>- 운영자 (반려) |
| 가능한 때 | 세미나 시작 24시간 전까지 |
| 취소 뒤 다시 신청 | - 모집 기간 안이면 가능<br>- 대기 순번은 맨 뒤로 |
