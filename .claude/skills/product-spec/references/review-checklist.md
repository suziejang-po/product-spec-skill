# 리뷰 체크리스트

골격 초안을 이 표로 판정한다. 판정은 정의됨, 불충분, 정의 없음 세 가지. 한 섹션에라도 명확히 있으면 정의됨, 있지만 모호하면 불충분, 어디에도 없으면 정의 없음. 섹션 간 내용이 어긋나면 불충분으로 두고 질문에 어긋난 두 곳을 함께 적는다. 판정 결과는 사용자에게 표로 보여주지 않고 `question-map.md`의 질문으로만 바꾼다

스펙에 해당 없는 소항목은 건너뛴다. 조건(노출 조건, 필수 여부, 권한)이 적혀 있으면 조건 밖 케이스는 동작하지 않는 것으로 보고, 조건 자체가 불완전하거나 기존 동작과의 관계가 불명확할 때만 지적한다

| 대항목 | 소항목 | 정의됨으로 보는 기준 |
|---|---|---|
| 사용자 및 권한 | 사용자 유형 정의 | 메뉴 구조 표 노출 조건 또는 문제의 타겟에 유저 유형이 있음 |
| 사용자 및 권한 | 권한별 접근 범위 | 유저 유형이 둘 이상이면 유형마다 보이는 화면과 기능이 구분됨 |
| 사용자 및 권한 | 인증 필요 조건 | 노출 조건에 로그인 여부가 있음 |
| 사용자 및 권한 | 권한 부족 시 처리 방식 | 권한 없는 유저가 진입했을 때 화면 또는 문구가 요구사항에 있음 |
| 사용자 및 권한 | 개인정보 노출 범위 | 이름, 연락처, 이력서 등 개인정보를 보여주는 기능이면 누구에게 어디까지 보이는지 있음 |
| 사용자 및 권한 | 플랫폼 범위 | 메타 또는 제약에 웹, 모바일 웹, 앱 범위가 있음 |
| 정책 | 핵심 정책 | 기능이 따르는 규칙(횟수 제한, 기간, 기본값)이 요구사항에 있음 |
| 정책 | 제한 정책 | 최대치, 금지 조건이 숫자로 있음 |
| 정책 | 예외 허용 조건 | 제한을 넘길 수 있는 경우가 있으면 조건이 있음 |
| 정책 | 정책 충돌 여부와 우선순위 | 기존 정책과 겹치는 기능이면 어느 쪽이 우선인지 있음 |
| 정책 | 관련 기존 정책 문서 | 제약과 참고에 링크가 있음 |
| 사용자 시나리오 | 대표 정상 경로 | 흐름도 또는 구현 상세 진입점 열로 시작부터 끝까지 이어짐 |
| 사용자 시나리오 | 주요 사용자 시나리오 | 유저 유형별 또는 상황별 경로가 흐름도에 있음 |
| 사용자 시나리오 | 조건 분기별 시나리오 | 흐름도의 분기마다 도착점이 있음 |
| 사용자 시나리오 | 진입 조건과 종료 조건 | 진입점 열이 채워지고, 완료 후 어디로 가는지 요구사항에 있음 |
| 기능 상세 명세 | 기능 개요 | 구현 범위 요약 첫 불릿과 솔루션이 있음 |
| 기능 상세 명세 | 화면, 영역, 액션별 동작 | 구현 상세 표에 화면과 기능 열이 채워짐 |
| 기능 상세 명세 | 입력값 정의와 검증 규칙 | 입력 필드가 있으면 타입, 필수, 검증, 오류 문구가 요구사항에 있음 |
| 기능 상세 명세 | 상태와 상태 전이 | 상태가 바뀌는 기능이면 상태 목록과 전이 조건 또는 상태도가 있음 |
| 기능 상세 명세 | UI 상태 정의 | 로딩, 빈 데이터, 오류 상태의 표시가 요구사항에 있음 |
| 기능 상세 명세 | 설정 여부에 따른 동작 | on/off나 옵션이 있으면 각 값에서의 동작이 있음 |
| 기능 상세 명세 | 예외, 실패, 오류 처리 | 네트워크 실패, 권한 없음, 중복 요청 시 동작이 있음 |
| 기능 상세 명세 | 입력, 저장, 수정, 삭제 규칙 | 데이터를 만들거나 바꾸는 기능이면 저장 시점과 수정, 삭제 가능 여부가 있음 |
| UI 명세 | 화면 목록 | 변경 페이지 표가 있음 |
| UI 명세 | 화면 목적 | 메뉴 구조 표 주요 기능 열이 채워짐 |
| UI 명세 | 컴포넌트 목록 | 신규 생성 화면이면 구성 요소가 요구사항에 있음 |
| UI 명세 | 컴포넌트별 역할 | 신규 구성 요소마다 동작이 있음 |
| UI 명세 | 디자인 링크 | 비주얼 표에 Figma 링크가 있음 |
| UI 명세 | 반응형 여부 | 웹이면 데스크톱과 모바일 차이가 제약 또는 요구사항에 있음 |
| 데이터 연동 명세 | 캐시 정책 | 목록이나 상태를 보여주는 기능이면 갱신 시점이 있음 |
| 데이터 연동 명세 | 동기화 정책 | 여러 화면이나 기기에서 같은 데이터를 보면 반영 시점이 있음 |
