# product-spec 스킬 사용 안내 (v4)

## 무엇인가

- Claude Code에서 "스펙 작성해줘"라고 하면 개발 킥오프용 Product Spec을 만드는 스킬
- 자료(코드, 첨부 문서, 대화, 기존 Confluence)에 있는 내용만 쓰고, 없는 내용은 빈칸으로 두고 질문함. 초안에 빈칸과 ⚠️가 많이 보이는 것이 정상
- 구현 상세는 번호, 진입점, 화면, 기능, 요구사항 5열 표. 흐름도는 그림으로 들어감

## 설치 (한 번)

- Claude Code에서 아래 한 줄
  - `이 스킬 설치해줘 https://github.com/suziejang-po/product-spec-skill`
- 준비물
  - Node.js (흐름도 그림 렌더. 없으면 그림 대신 확인 필요 표시)
  - Atlassian MCP 연결 (Confluence 게시. 없으면 로컬 파일까지만)
  - Amplitude MCP 연결 (선택. 이벤트명이 실제로 있는지 자동 확인)
  - Atlassian API 토큰 (선택. 본인 것만. 있으면 흐름도가 첨부 이미지로 크게 들어감. 없으면 편집 화면에서 한 번 붙여넣기)

## 사용 순서

1. 프로젝트 폴더에서 Claude Code 실행. 레포가 없으면 빈 폴더도 가능
2. 자료를 한 줄로 알려 주며 요청
   - 예: `인재풀 제안 상세 화면 배너 실험 스펙 써줘. 자료는 Confluence 4914709425`
3. 첫 실행이면 도메인 팩 질문 5개 (어느 화면, 메뉴 경로, 참고 문서, 용어, API). 아는 것만 답하고 나머지는 `모름`. 같은 폴더에서는 다음부터 묻지 않음
4. 골격 초안 확인. 방향이 틀리면 이때 말함
5. 질문에 답하기. 5개 안팎씩 최대 2회. 번호와 답만 적음. `모름`이라고 하면 문서에 `⚠️ {항목} → {담당} 확인 필요`로 남음
6. 본문 저장 확인. HTML 프로토타입을 만들지 물으면 필요할 때만 선택
7. Confluence 게시를 원하면 `올려줘`. 처음이면 "제품 출시 미정" 아래 (작성중) 페이지로 생성

## 답하는 요령

- 선택지에 없는 답은 자유롭게 씀. 선택지는 참고
- 추측으로 답하지 않음. 모르면 `모름`. 문서에 확인 필요로 남는 것이 지어낸 값보다 낫다
- 질문이 너무 많으면 `그냥 만들어`. 남은 항목은 전부 ⚠️로 남김

## 결과물 위치

- `docs/specs/{스펙 이름}/spec.md` 본문
- `docs/specs/{스펙 이름}/sources.md` 어떤 문장이 어디서 왔는지 (확인 또는 구술)
- `docs/specs/{스펙 이름}/diagrams/` 흐름도 코드와 그림
- `docs/spec-context.md` 프로젝트 공통 도메인 팩. 다음 스펙에서 재사용
- 사내 API와 이벤트명이 들어가므로 공개 레포에는 올리지 않음

## Confluence 게시와 흐름도

- 게시는 로컬 파일을 정본으로 전체 덮어쓰기. 다른 사람이 Confluence에서 직접 고친 내용이 있으면 덮어쓰기 전에 물어봄
- 흐름도
  - 토큰이 있으면 첨부 이미지로 자동 삽입 (⚠️ 2026-09-18 기준 실사용 검증 전)
  - 토큰이 없으면 페이지에 "사용자 흐름도 자리" 안내 상자가 들어감. 편집 화면에서 그 자리에 `/mermaid`를 치고 `diagrams/flow.mmd` 내용을 붙여넣으면 그림이 됨

## 고치기

- 같은 폴더에서 `스펙 수정해줘, {바꿀 내용}`. 바뀐 섹션만 다시 씀. 전체를 다시 만들지 않음
- 흐름이 바뀌면 그림도 다시 렌더됨

## 업데이트

- 실행할 때 새 버전이 있으면 한 줄 안내가 뜸. `스킬 업데이트해줘`라고 하면 갱신
- 규칙이나 양식을 바꾸고 싶으면 장수지에게 요청. 포크 main에 반영되면 전원에게 안내가 뜸

## 알려진 한계 (2026-09-18)

- 흐름도 자동 삽입은 그림 데이터가 크면 실패함. 위 수동 붙여넣기로 대체
- 사내 API 스펙 MCP(asp)가 없는 환경에서는 API 경로를 문서에 적힌 것만 표기
